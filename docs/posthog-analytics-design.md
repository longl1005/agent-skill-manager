# PostHog 安装与活跃度统计设计

## 目标

使用 PostHog Cloud 在不影响桌面应用启动和用户隐私的前提下，统计：

- 激活安装量：每个匿名安装首次成功启动时记录一次；
- 活跃趋势：每次应用成功启动时记录一次；
- 版本、操作系统和 CPU 架构分布。

## 范围与非目标

本次仅实现安装与活跃度统计，不记录扫描、搜索、Skill 安装/导入或错误事件；不接入 Sentry。

## 架构

前端新增独立的 analytics 模块，作为 PostHog SDK 的唯一调用点。应用入口只调用模块提供的初始化和启动记录接口，设置页只读取和更新一个“匿名使用统计”开关。其他 UI、路由和业务模块不直接依赖 PostHog。

该模块负责：

1. 读取本地统计偏好；
2. 生成并持久化随机匿名安装 ID；
3. 在构建时提供的 PostHog Key 存在且开关开启时初始化 SDK；
4. 发送固定的启动事件；
5. 在关闭开关、缺少 Key 或网络失败时安全地不执行上报。

## 事件与属性

### `app_first_launch`

每个匿名安装 ID 只发送一次。该事件用于统计真实启动过应用的安装数量，而不是安装包下载次数。

### `app_opened`

每次应用成功启动发送一次，用于日活和启动趋势分析。

两个事件都只附带以下属性：

- `app_version`：应用版本；
- `platform`：`macos`、`windows` 或 `linux`；
- `arch`：例如 `arm64` 或 `x64`。

## 隐私与控制

统计默认开启；设置页提供“匿名使用统计”开关。关闭后立即停止 SDK 初始化、事件发送和本地事件排队，且偏好在下次启动继续生效。

不得收集用户名、邮箱、硬件或系统设备 ID、本地文件路径、Skill 内容、扫描结果、搜索内容或用户操作细节。安装 ID 必须是应用生成的随机值，不得从设备标识推导。

## 配置与故障处理

PostHog Key 使用构建时环境变量注入，不能硬编码到源代码。未提供 Key 的开发构建和本地构建必须自动禁用统计。

网络不可用、PostHog 服务不可达或 SDK 初始化失败时，应静默跳过统计，不能阻塞或降低应用启动、扫描和界面交互。统计模块不得抛出未处理错误到调用方。

## 测试

- 新安装首次启动发送一次 `app_first_launch` 和一次 `app_opened`；
- 后续启动只发送 `app_opened`；
- 关闭统计后不会初始化 SDK 或发送事件；
- 没有 PostHog Key 时不会初始化 SDK 或发送事件；
- SDK 异常和网络失败不会影响应用启动。

## 发布后验证

发布安装包后，使用干净的本地应用数据目录启动一次，确认 PostHog 收到上述两种事件，并确认关闭开关后不再产生新事件。下载量继续以 GitHub Releases 的 Release Asset 下载计数为准。
