# Agent 卸载功能设计

## 目标

让用户从 Agent Skill Manager（ASM）卸载一个已检测到的 Agent，并可逐项选择移除该 Agent 的应用组件、技能与数据目录、以及 ASM 相关配置。功能支持 macOS 与 Windows，覆盖常见包管理器、桌面应用和编辑器扩展。

主技能库 `~/.asm/skills` 不属于 Agent 卸载范围，绝不删除。

## 入口与交互

入口位于“设置 → 已检测到的 Agent”卡片内的“危险操作”区域，使用独立的“卸载 Agent…”按钮。该入口与启用/关闭和技能路径配置相邻，但不放在 Agent 详情页，避免将浏览技能的页面与删除整个应用的操作混在一起。

点击后进入三步向导：

1. **选择组件**：按来源分组显示仅经验证归属于该 Agent 的组件。用户可分别勾选 CLI、编辑器扩展、桌面应用、Agent 数据与技能目录、ASM 配置。
2. **预览**：展示每个已选组件将运行的精确卸载程序及参数、将删除的路径、是否需要管理员权限、以及保留项（特别是主技能库）。
3. **确认与结果**：用户输入 Agent 显示名称才可执行。完成后以组件为单位显示“已卸载、跳过、失败”，失败项可单独重试。

## 组件模型

后端将每个候选项返回为统一组件记录，至少包含：

- 唯一 ID、Agent ID、组件类型和显示名称；
- 安装来源及已验证归属依据；
- 固定的执行器和参数列表，或受保护的删除路径；
- 是否需要管理员权限；
- 可选/默认选择状态和不可执行原因。

组件类型包括：包管理器 CLI、IDE 扩展、桌面应用、Agent 数据与技能目录、ASM Agent 配置、仅供手动处理的未知组件。

前端只渲染这些结构化记录；前端不得构造 shell 命令或自由传递命令字符串。

## 检测与平台适配

按 Agent 的描述信息和当前操作系统注册对应的卸载来源检测器。一个 Agent 可产生多个组件，用户逐项选择。

支持来源：

- CLI 包：npm、pnpm、yarn、pip、pipx、Cargo、Homebrew；
- Windows 包管理器：winget、Chocolatey、Scoop；
- 编辑器扩展：VS Code、Cursor 等支持命令行卸载扩展的宿主；
- macOS 桌面应用：已验证的 `.app`；
- Windows 独立安装项：Windows“已安装应用”注册表记录。

Windows 注册表卸载项必须同时匹配显示名、发布者和安装位置。winget/choco/scoop 等必须在各自已安装清单中匹配确定的包标识。无法证明归属的安装来源只显示为“需手动卸载”，不能执行一键卸载。

macOS 桌面应用优先移入废纸篓；包管理器安装项按对应包管理器标准卸载。Windows 需要提升权限时，由系统 UAC 发起授权。

## 执行与保护规则

卸载按用户选择的组件逐项执行，不承诺事务性回滚。每项的失败不阻断其余已选项；所有结果和错误被保留到结果页。

删除路径必须经后端验证为该 Agent 已知的数据根目录或当前生效的自定义技能目录。以下项目一律拒绝删除：

- `~/.asm/skills` 及其内部内容；
- 不属于该 Agent 已知根目录的路径；
- 共享目录；
- 软链接的目标。

删除 Agent 技能目录中的软链接时，只删除链接本身。删除 ASM 配置时，移除该 Agent 的自定义路径、禁用状态和排序记录；不修改其他 Agent 的配置。

命令执行采用固定的程序路径和参数列表，禁止 `sh -c`、`cmd /C` 或把前端传来的字符串作为 shell 命令执行。

## 刷新与结果

完成后，前端刷新 Agent 扫描、主技能库视图和 Agent 配置状态。完全卸载后 Agent 不再出现在“已检测到的 Agent”中；若有失败或仍存在未选组件，结果页保留具体说明，不把 Agent 标记为已完全卸载。

## 测试

Rust 测试覆盖来源检测、命令构建、Windows 注册表三重匹配、危险路径拒绝、主技能库与软链接目标保护、逐项执行和部分失败结果。前端测试覆盖组件选择、预览、名称确认门槛、执行中禁用、结果展示与单项重试。平台相关测试采用虚拟安装清单和路径，避免真实调用包管理器或删除用户文件。

## 非目标

本期不支持对无法确认来源的应用进行猜测性卸载；不提供批量卸载多个 Agent；不删除 ASM 主技能库或其他 Agent 的资源。
