# Agent 本地副本替换为软链接

## 目标

当 Agent 的技能目录包含一个与主技能仓库同名、但不是软链接的真实目录时，明确标识其为本地副本，并允许用户在确认后将其删除并替换为指向主库的软链接。

## 状态与界面

Agent 技能卡基于主库匹配和文件系统状态展示以下状态：

- 主库不存在：显示“上传至主库”。
- 主库存在且 Agent 路径是指向该主库技能的软链接：显示“已在主库 · 软链接”。
- 主库存在且 Agent 路径是实际文件或目录：显示“已在主库 · 本地副本”和“替换为软链接”按钮。
- Agent 路径是软链接、但不指向对应主库技能：显示“外部软链接”，不显示删除或替换操作。

“替换为软链接”只显示在已识别为本地副本的技能卡上。

## 替换流程

1. 用户点击“替换为软链接”。
2. 应用显示确认弹窗，说明会永久删除当前 Agent 目录的本地副本；主库及其他 Agent 不受影响。
3. 用户确认后，后端重新校验主库技能存在且 Agent 路径仍是非软链接的本地副本。
4. 后端删除该 Agent 路径，并创建指向对应主库技能的软链接。
5. 后端更新 SQLite 中该 Agent/技能的链接状态和活动记录；前端重新扫描并刷新主库数据。

## 安全边界

- 扫描必须是只读的：绝不因为内容相同而自动替换本地副本。
- 替换命令只允许删除 Agent 技能根目录下的单个目标条目；目标名称必须来自已扫描的技能，不接受路径片段。
- 若目标已是任意软链接、主库技能缺失或文件系统状态在确认后发生变化，命令失败且不删除任何内容。
- 本次按用户确认的策略执行直接删除，不创建备份。

## 验证

- 后端测试覆盖本地目录替换成功、主库不存在、目标已是软链接和非法技能名。
- 前端测试覆盖三种状态、确认弹窗和成功后的重新扫描。
