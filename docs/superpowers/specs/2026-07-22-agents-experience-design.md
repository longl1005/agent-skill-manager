# Agents 体验设计

**日期：**2026-07-22  
**状态：**设计已确认，等待书面 Spec 审阅  
**范围：**定义 Agents 列表、单 Agent 详情工作台，以及从中央 Skill 仓库向当前 Agent 添加 Skill 的交互。

## 目标

让用户先看到本机实际检测到的 Agent，再快速进入某一个 Agent 的 Skill 工作台，理解它安装了什么，并从中央仓库选择 Skill 发起同步。

## 信息架构

```
Agents 列表
  └─ 点击已检测到的 Agent
       └─ Agent 详情 / Skill 工作台
            └─ 添加 Skill 弹层
                 └─ 中央 Skill 仓库多选与同步预览
```

## Agents 列表

- 只展示本机已检测到的 Agent；未安装、未检测或仅计划支持的 Agent 不显示。
- 页面标题显示 “Agents · N”，`N` 为检测到的 Agent 数量。
- 使用“能力控制台”视觉方向：深色画布、克制边框、清晰状态徽标与强主标题；窗口变窄时允许减少列数。
- 顶部显示环境标签、检测数量和说明文字，右侧提供次级操作“重新扫描”。
- 已检测 Agent 以带层级的卡片展示：Agent 图标、显示名称、`N Skills`、Roots 数量、检测状态徽标和 “Open workspace →” 进入动作。
- 当仅检测到少量 Agent 时，保留低对比度的说明区域，提示用户在安装新 Agent 后重新扫描；不展示未检测 Agent 的真实卡片。
- 点击整张卡片进入该 Agent 的详情页。列表页不承担根目录、问题或 Skill 明细。
- 无检测结果时，显示空状态与“运行扫描”入口，而不是支持的 Agent 清单。

## Agent 详情 / Skill 工作台

### 顶部

- 左侧：Agent 图标、名称、Skill 数量徽标；下一行显示主要 Skill 根路径及“技能数 / 冲突数 / 已同步数”的摘要。
- 右侧：Skill 搜索框、刷新、网格/列表视图切换，以及唯一绿色主操作“添加 Skill”。
- 刷新重新扫描当前 Agent；在扫描能力不可用时按钮禁用并说明原因。

### Skill 内容区

- 默认采用三列卡片网格，允许用户切换列表视图；卡片区域是详情页的视觉核心。
- 每张 Skill 卡片显示：名称、截断描述、文件数量或入口文件信息、安装来源/范围标签（例如“仅本地”），并以分隔线将内容区与操作区分开。
- 卡片的底部操作预留导入/导出、删除等位置；本期尚未具备写操作时，必须禁用并提供原因提示，不得假装已经执行。
- 搜索只过滤当前 Agent 已安装的 Skills，按名称和描述匹配；结果即时更新。
- 没有 Skills 时，保留顶部 Agent 信息并显示“从中央仓库添加 Skill”的空状态入口。

## 添加 Skill 弹层

- 点击“添加 Skill”打开居中模态弹层，不离开 Agent 详情页。
- 弹层上下文固定为当前目标 Agent，例如“添加到 Claude Code”。
- 内容来自中央 Skill 仓库：提供搜索、可选分类/来源筛选、Skill 名称、描述和安装状态。
- 支持多选；底部固定显示已选择数量、取消按钮和“同步到 {Agent 名称}”按钮。
- 点击同步前展示预览：新增数量、已存在数量、内容冲突数量，以及每一种结果的处理说明。
- 用户确认后才创建同步任务；绝不静默覆盖当前 Agent 中的文件。

## 本期与后续边界

本设计定义完整的用户任务流，但实际文件写入依赖后续 Sync Engine：

- 当前 Discovery MVP 可以展示 Agents 列表和详情中的只读库存。
- “添加 Skill”按钮、弹层、中央库选择和同步预览可先实现为 UI/计划层。
- 执行同步、冲突解析、删除和导入/导出仅在 Sync Engine 有明确计划与确认机制后接入。
- 中央 Skill 仓库是领域概念，不要求本期立即引入远端服务；其初始数据源和持久化方式由单独规格决定。

## 验收标准

1. 未检测到的 Agent 不出现在 Agents 列表。
2. 点击已检测 Agent 后，可看到其只读 Skill 工作台与当前扫描数据。
3. 当前 Agent 的搜索不会混入其他 Agent 的 Skills。
4. “添加 Skill”弹层明确显示目标 Agent、支持多选并在确认前显示同步预览。
5. 所有尚未实现的写操作均明确禁用或进入计划状态，不伪造成功。
6. 在有、无 Skill，以及扫描失败三种状态下，页面均能解释当前状态和下一步。
